API Reference

Automate SLightSFTP through the same REST API the web GUI uses

REST API

The web GUI is a client of a JSON REST API served by the web GUI server (default http://localhost:3000, or https:// when HTTPS is enabled). Everything the GUI can do, scripts can do too. Start the server from the desktop app (Listeners → Web GUI Server → Start) or headless with WEB_PORT=3000 WEB_HTTPS=true node dist/web-only.js.

# sign in and keep the session cookie
curl -k -c jar -H 'Content-Type: application/json' \
     -d '{"username":"admin","password":"<your password>"}' https://localhost:3000/api/login

# list connected clients
curl -k -b jar https://localhost:3000/api/sessions

# create an SFTP listener on port 2222
curl -k -b jar -H 'Content-Type: application/json' \
     -d '{"name":"Partners","protocol":"SFTP","bindingIp":"0.0.0.0","port":2222,"enabled":true}' \
     https://localhost:3000/api/listeners

Live events: open a WebSocket to the same host and port (ws:// or wss://) to receive { "type": "activity", "data": { listenerId, username, action, path, success, timestamp } } messages for every login, transfer and admin action.

Authentication

Sign in to receive an HttpOnly sessionId cookie (also Secure when the GUI is served over HTTPS). Every other /api endpoint requires it and answers 401 without it. While a password change is pending, only the change-password, user and logout endpoints are available (others answer 403 with requirePasswordChange: true).

POST /api/login

Body { username, password }. Returns { success, username }, plus requirePasswordChange: true when a new password must be chosen. Only users with GUI access may sign in.

POST /api/change-password

Body { newPassword, currentPassword }. currentPassword is not needed while a change is being forced. New passwords need at least 8 characters and must differ from the default and the current one.

POST /api/logout

Ends the session.

GET /api/user

The signed-in user: { username }.

GET /api/server-identity

{ sshHostKeyFingerprint } — give this to users so their SFTP client can verify the server.

Listeners

FTP and SFTP servers. tlsMode (FTP only) is none, optional or required.

GET /api/listeners

All listeners.

GET /api/listeners/:id

One listener, or 404.

POST /api/listeners

Body { name, protocol: 'FTP'|'SFTP', bindingIp, port, enabled, tlsMode? }. Enabled listeners start immediately.

PUT /api/listeners/:id

Body { name, bindingIp, port, enabled, tlsMode? }. A running listener is restarted with the new settings.

DELETE /api/listeners/:id

Stops (if running) and deletes the listener.

POST /api/listeners/:id/start

Start; 400 if already running or disabled.

POST /api/listeners/:id/stop

Stop.

POST /api/listeners/:id/restart

Restart.

GET /api/listener-statuses

[{ listener, running }] including the web GUI itself (id: -1, protocol HTTP/HTTPS).

Users

Password hashes are never returned.

GET /api/users

All users.

GET /api/users/:username

One user, or 404.

POST /api/users

Body { username, password, passwordEnabled, publicKey?, guiEnabled, mustChangePassword? }.

PUT /api/users/:username

Body { password?, passwordEnabled, publicKey?, guiEnabled, mustChangePassword? }. Optionally also listeners (ids), virtualPaths and permissions arrays to replace the user's access in one call.

DELETE /api/users/:username

Delete the user.

GET /api/users/:username/subscriptions

Listener ids the user may connect to.

POST /api/users/:username/subscriptions

Body { listenerId }.

DELETE /api/users/:username/subscriptions/:listenerId

Revoke access to a listener.

GET /api/users/:username/virtual-paths

The user's virtual path mappings.

POST /api/users/:username/virtual-paths

Body { virtualPath, localPath, canRead, canWrite, canAppend, canDelete, canList, canCreateDir, canRename, applyToSubdirs }.

DELETE /api/users/:username/virtual-paths/:id

Remove a mapping.

GET /api/users/id/:userId/listeners

Listener ids by user id.

GET /api/users/id/:userId/virtual-paths

Virtual paths by user id.

GET /api/users/id/:userId/permissions/:listenerId

Listener-level permissions, or null.

Sessions

GET /api/sessions

Connected FTP/SFTP clients: { sessionId, username, ipAddress, connectedAt, listenerId, listenerName, protocol }.

DELETE /api/sessions/:sessionId

Disconnect a client; 404 if it already left.

Files

Paths are virtual paths of the given user; .. and anything outside the user's mappings is refused with 403.

GET /api/files/browse?username=&path=

{ files: [{ name, type, size, modified }], currentPath }.

GET /api/files/download?username=&path=

Downloads a file (Content-Disposition: attachment).

Activity log & settings

GET /api/activity?limit=

Most recent entries (default 100).

GET /api/activity/count

{ count }.

DELETE /api/activity

Body { beforeDate? } (ISO 8601). Without a date the whole log is cleared. Returns { success, count }.

GET /api/activity/old-stats?retentionDays=

Entries older than the retention period: { count }.

POST /api/activity/cleanup

Apply the retention period now: { success, count }.

GET /api/settings

All settings, e.g. logRetentionDays, webHttps, tlsCertPath, tlsKeyPath.

GET /api/settings/:key

{ key, value }.

PUT /api/settings/:key

Body { value }.

Command line

npm start            # build and run the desktop app
npm run start:web    # build and run headless with the web GUI (WEB_PORT, WEB_HTTPS)
npm test             # unit, integration and end-to-end tests
npm run test:e2e     # browser and desktop GUI tests (Playwright)
npm run dist:linux   # build AppImage + .deb
npm run dist:win     # build the Windows MSI
